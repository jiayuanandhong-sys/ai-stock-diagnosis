1. 根因分析

1.1 Bug 1：PEG 失败后仍可能冻结数据集并允许 Runner 执行

根因（build_dataset.py 原 L939）：冻结判定 frozen = (c["status"]=="FROZEN" and report["overall"]=="PASS") 本身正确，但清单状态回退分支 "status": "FROZEN" if frozen else c["status"] 的回退值就是案例自身的 "FROZEN"（数据集构建时所有非 BLOCKED 案例的 status 字段）——overall=FAIL 时 frozen=False，清单却照样标 FROZEN。本会话上午的运行日志留有直接实证： 「PEG 校验: overall=FAIL … 冻结清单：FROZEN=33」。脚本退出码恒为 0。

Runner 侧（Bug 1b）：main() 把 peg_report_overall 只写进结果元数据、 从不强制校验；对被误标 FROZEN 的案例照常执行评测。

复现实证（修复前，logs/bugfix_repro.log）：注入 overall=FAIL 的 PEG 报告 → 清单中 C1/C2 仍标 FROZEN，旧有效清单被覆盖，退出码 0。缺陷确认。

1.2 Bug 2：部分通过的案例被错误标记为 PASS

根因（run_evals.py 原 L700-706）：案例聚合为 if "FAIL" in statuses: FAIL; elif "PASS" in statuses: PASS; else: NOT_RUN ——只要存在一条 PASS、零 FAIL 即 PASS，NOT_RUN 断言被完全吞掉。

复现实证（修复前）：v1.0 运行结果中 17 个案例被标 PASS 但各含 1–2 条 NOT_RUN 必需断言（含任务点名的 L4-016/017/018/019：禁词扫描 PASS + LLM Judge NOT_RUN → 整案例 PASS）。缺陷确认。
