AI 量化个股诊断产品 · MVP 范围决策方案

决策日期：2026-10-17 ｜ 方案性质：MVP 第一版取舍建议（用户尚未批准，属决策草案） ｜ 依据：mvp-prioritization v1.1.2 方法论
目标市场 / 辖区中国大陆 A 股
资质路径规划与持牌机构合作（未落地）
MVP 发布范围自己 + 小范围熟人灰度
团队资源单人 + AI 辅助开发

〇、决策结论（一页看懂）

✅ 第一版做：技术指标解释以「个股诊断报告」为核心交付物：规则层计算指标 → LLM 只做解释层。验证"散户是否需要看得懂的个股诊断"这一最关键假设，合规暴露最小，单人 4–6 周可闭环。
⏭ 下一版做：自动选股价值验证周期长（需等收益兑现）、"荐股"合规属性强、因子+回测工程量单人不可承受、同花顺/东财已做烂。V1 用「批量自选股诊断」替代性观察需求信号。
⛔ 第一版不做：AI 投资建议属决策型 AI + 证券投资咨询业务，被"持牌合作未落地"硬阻断。V1 以"诊断+解释+风险提示"逼近体验但不输出买卖建议；持牌合作与法务核验并行推进，作为 V2 依赖。

一、候选功能对比

功能用户任务Kano（均为 PM 假设）档位产品价值 / 证据实现成本（单人）主要风险
技术指标解释 散户拿到一只股票，看不懂 MACD/RSI/KDJ/量价/均线信号意味着什么，想要"看得懂的体检报告" 期望（假设） 必须做 教育/信息属性，直接命中"个股诊断"题眼；LLM 擅长的解释层；竞品（同花顺 AI、东财妙想）证明需求存在但解读深度参差 （竞品认知为 PM 既有研究背景，未经本次系统核验） 低-中：数据接口 + 指标计算（规则，确定性）+ LLM 解释（模板约束），约 4–6 周闭环 幻觉（数值必须全部来自计算层）；解释质量需抽检评测
自动选股 用户不知道买什么，想让系统从全市场筛出候选 魅力（假设） 后续做 表面吸引力高，但价值验证周期长——选股好坏需等收益兑现，MVP 阶段无法快速证伪；免费竞品已充分供给 高：因子库 + 回测框架 + 全市场数据质量工程，约 6–10 周；且验证周期以月计 "荐股"属性强于"解释"，公开输出合规风险上升；效果差直接砸品牌
AI 投资建议 用户想要"该不该买/卖/补仓/止损点位" 合规安全组，不进 Kano V1 不做（阻断） 付费意愿可能最强，但属证券投资咨询业务范畴，无资质公开提供即触红线；熟人灰度阶段也无需冒此险 开发本身 2–3 周，但被持牌合作协议（责任划分、输出署名、审核流程）阻断，周期不可控 决策型 AI 的幻觉与责任归属；监管处罚；合作方背书风险
取舍逻辑：MVP 要验证的最关键不确定性是"散户是否真的需要、并持续使用看得懂的个股诊断"（需求假设），而不是"我们的选股/建议准不准"（效果假设，验证周期长且当前无资质）。三个功能中只有「指标解释」能同时满足：验证速度最快 × 合规暴露最小 × 单人可实现。

功能点Kano 假设验证方式（内测期）
自然语言个股诊断报告（核心指标解释）期望 无则减分复用率 + 对照组（裸指标面板）偏好访谈

三、合规与安全底线（四级分类）

L-4 风险评估建议 —— V1 生效（通用安全实践，作为强制约束执行）

底线项实现方式状态
免责声明每份报告固定文案："本报告为指标数据解释与风险提示，不构成任何投资建议"V1 必做
禁止指令性表述Prompt 约束 + 输出正则过滤：拦截"买入/卖出/加仓/满仓/止损点位"类建议性话术V1 必做
数据来源与生成时间标注报告注明数据截止日期与数据源V1 必做
全量留痕输入、计算结果、模型输出、用户反馈全部落日志V1 必做
异常兜底数据缺失/API 失败 → 降级展示原始指标表 + "暂无法生成解释"V1 必做
紧急停用条件内测期间发现系统性错误输出 → 立即下线修复后重测V1 必做

L-1 疑似法定要求 —— V2 公开发布/输出建议前必须法务核验（核验前一律不输出）

事项疑似依据状态
证券投资咨询业务资格《证券、期货投资咨询管理暂行办法》（1997，国务院证券委员会发布）：未取得资格从事证券投资咨询业务涉嫌违规条款号待法务核验，核验前按 L-4 处置
证券服务机构备案与行为规范《证券法》（2019 年修订）：投资咨询相关备案要求及禁止行为（承诺收益、代客操作等）条款号待法务核验
数据源商用授权akshare / Tushare 等免费数据接口的商用条款；通达信数据仅限个人使用范围公开/商业化前必须确认
说明（V6/V9 硬规则）：以上法规名真实存在，但本方案未逐条核对条款号，故全部标注为"疑似法定、待法务核验"，不虚构条款细节。熟人灰度 + 教育/信息定位的 V1 输出，以 L-4 底线为强制约束即可；任何形式的"买卖建议"输出与公开发布，均以上述核验完成为前置条件。

四、MVP 范围界定（四档）

档位内容
第一版必须做 ① 个股诊断报告：输入代码 → 5–8 个核心指标（均线系统、MACD、RSI、KDJ、量价关系、换手率、估值摘要）
② LLM 自然语言解释层：严格引用规则层计算数值，逐指标解读 + 综合小结
③ 免责声明与风险提示（固定文案）
④ 反馈入口：有用 / 没用 / 纠错（每份报告级）
⑤ 异常兜底与留痕日志
合计 5 个功能点（课程经验参考值 4–6，非上限）
公测/下一版应该做批量自选股诊断（选股需求观察位）；报告结构迭代（依据内测反馈）；解释质量评测集系统化
后续可做自动选股（H1 验证通过后）；与持牌机构合作下的合规建议输出（V2）
明确不做 / 不允许V1 输出任何买卖建议或点位（严格禁止自动执行）；实盘/模拟交易接口；多市场（港美股）；收益类、荐股类自动生成的社交媒体内容

五、最小用户闭环

1 输入股票代码 / 名称（内测白名单用户）
→
2 数据拉取日线行情、量价、基础财务；数据校验
→
3 规则层计算指标数值与信号状态（确定性，不经 LLM）
→
4 LLM 解释结构化模板约束，只引用计算层数值，禁建议表述
→
5 输出报告诊断报告 + 免责声明 + 数据来源时间
→
6 反馈回流有用/没用/纠错 → 日志；纠错人工复核

失败与兜底：数据缺失/接口异常 → 降级为原始指标表；模型 API 超时 → 重试一次后降级；解释与数值矛盾 → 以数值为准并标记待修复。人工接管：纠错反馈 48 小时内人工复核（内测期由本人承担）。

六、技术分工（规则 / LLM / 人工）

层职责技术选型约束
规则层（确定性）数据拉取与校验、全部指标计算、信号状态判定禁止用 LLM 做任何数值计算；保证数值 100% 可复现
LLM 层（生成）仅解释生成：把结构化数值翻译为散户语言输入为结构化 JSON；系统提示词含禁止事项清单；输出正则过滤；模型选型按单次成本 × 解释质量约束评估
人工纠错复核、评测抽检（30% 抽样）、内测运营AI 可辅助评测打分，但通过/失败标准由人把关

七、验证标准（显式样本口径）

假设验证动作通过标准样本与口径失败后
H1 需求：散户需要"看得懂的个股诊断"并持续使用 10–20 人熟人内测，2 周真实使用 ≥50% 用户复用 ≥3 次，且 ≥30% 主动推荐他人 内测用户全量；复用以留痕日志为准 回到定位：访谈诊断是"不需要"还是"报告结构不对"，必要时重新定义目标用户
H2 质量：解释层事实准确 构建评测集 + 30% 随机抽样人工复核 指标数值错误 = 0（计算层单测）；解释事实性错误率 <5%（在 30 条人工复核样本下）；指令性话术出现 0 次（在 N=100 条生成样本下） N=100 只随机股票生成样本；30% 抽样人工复核；零违规为样本观察，不等于全量零风险 加严模板约束 / 更换模型 / 缩小解释范围后重测；仍失败则砍掉 LLM 层，仅保留规则信号
H3 决策影响：诊断改变用户对个股的理解 内测结束访谈 ≥30% 用户能举出"看完报告改变判断/操作前必看"的具体例子 访谈定性证据，不做百分比外推 调整报告信息结构（可能用户要的不是指标解释而是结论先行）
口径声明：上述百分比门槛为 PM 设定值（非行业基线），H1/H3 无历史基线可参照，属"待基线确认后可修订"的占位。评测集的系统化构建建议后续走 eval-dataset-design 流程（本次未调用，列为待办）。

九、关键风险与待用户确认

  • 数据源风险：免费接口（akshare 等）稳定性与商用条款均未确认，V1 用作灰度可接受，V2 前必须解决。
  • 竞品压力：同花顺 AI、东方财富妙想已提供免费的 AI 解读与选股，差异化必须想清楚（候选方向：诊断深度、多空逻辑透明、无广告干扰、散户语言），建议后续走 competitor-analysis 流程系统核验。
  • 持牌合作节奏：谈判与法务核验建议与 V1 开发并行启动，否则 V2 时间表完全被动。
  • 需用户确认的决定：① 是否接受"AI 投资建议"整体移出 V1；② H1–H3 门槛数值是否认可；③ 内测人群名单（10–20 人）与周期（2 周）；④ 持牌合作目标机构是否已有意向对象。

课程思维辅助（旁路补充，3 条）

【高老师建议·课程明确｜M31】区分生成型与决策型 AI。 发现：三个候选功能横跨两种 AI 形态：指标解释是"生成内容"，投资建议是"对行动选择的判断"——后者对准确性、可解释性和责任的要求完全不同。 出处：《知乎13期AI产品经理PDF合并31-40.pdf》，PDF 第 339 页（M31，提炼类型：直接）。 AI 应用建议：V1 把 LLM 严格限定在生成解释层，一切决策性判断（信号状态）由规则层给出并标注计算依据，为将来接入持牌建议能力留出清晰的责任边界。（此建议为 AI 对当前项目的应用，非高老师对本产品的评价）
【高老师建议·课程明确｜M10】从供给侧转向需求侧思维。 发现："自动选股"吸引力大，但部分属于"我们能做所以想做"的供给侧冲动；散户的未满足需求究竟是"帮我选"还是"帮我看懂"，目前只是 PM 假设。 出处：《知乎13期产品经理基本功PDF合并.pdf》，PDF 第 324 页（M10，提炼类型：直接）。 AI 应用建议：内测访谈第一问设计为："你最近一次看某只股票的指标时，具体卡在哪一步？"用真实回答校准 V1.5 方向，而不是直接堆选股功能。
【高老师课程启发·AI归纳｜X03，支撑 M33】对方案保持替代路径意识。 发现："自动选股"的第一版替代验证路径已内置：批量自选股诊断可以低成本观察用户是否自发把它当选股器用。 支撑出处：M33"发现痛点→Demo→验证→规模化"，《知乎13期AI产品经理PDF合并31-40.pdf》，PDF 第 502 页（提炼类型：案例推演；X03 为跨章节归纳）。 AI 应用建议：V1.5 上线批量诊断后，把"用户主动询问能否按条件筛选全市场"的频次作为选股需求强度的领先指标。
证据与口径说明：本方案中功能价值判断基于用户给定的三个候选功能与已确认的四项约束（辖区/资质/范围/资源），无外部新采集数据；竞品对比为 PM 既有研究背景，未经本次系统核验；所有百分比门槛为 PM 设定占位值；所有 Kano 分类为"待验证的 PM 假设"。法规名真实存在但条款号未经核验，相关项均标"疑似法定、待法务确认"。
